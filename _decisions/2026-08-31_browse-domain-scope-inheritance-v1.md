## この記録で残す罠

1. **子が親より閲覧できるものが多い構造を作らない。** Categoryは Root の部分集合（§1）
2. **同一Domain内の縦方向に「需要判定」を持ち込まない。** 需要判定はDomain間だけ（§2）
3. **「深さで軸を変えない」と書かない。** HOMEにナビが無いことと矛盾する（§3）
4. **軸を1本足すと、休眠していた表示グループのバグが起きる。** 036違反が2件出た（§5）
5. **チェッカーに書いただけの設定は検査していない。** 門番の条件を必ず読む（§6）

## 0. 何が起きたか

037 で CLOSE した状態を PC / Mobile 4面ぶん実画面で並べたところ、
**RIG ROOT から RIG Category へ1段降りた瞬間だけ、
`パーツ` という新しい閲覧モードが出現する**ことに違和感が出た。

```
すべてのRCカー（RIG ROOT）      トップ / RIG / LOG
Rock Crawler（RIG Category）   トップ / RIG / パーツ / LOG
```

Rock Crawler は「すべてのRCカー」をカテゴリで絞ったスコープにすぎない。
**部分集合なのに親より閲覧できるものが多い**のは説明できない。

イタヤ所見:

> クローラーしかやらない人にとっては Rock Crawler が自分の総合トップになる。
> 将来マイカテゴリ設定でここをトップ相当にしたい。
> そう考えるとここにパーツが無いのはおかしい。
> でもそれなら すべてのRCカー にもパーツがあっていいのでは。

この過程で「ROOT自体が要らないのでは」という説も出たが、**採らない**（§4）。

## 1. 🔴【L1】同一Domain内では Root → Category で閲覧モードを継承する

| Domain | Root | Category |
|---|---|---|
| **RIG** | すべてのRCカー<br>**トップ / RIG / パーツ / LOG** | Rock Crawler<br>**トップ / RIG / パーツ / LOG** |
| **PARTS** | すべてのパーツ<br>**トップ / パーツ / LOG** | モーター・ESC<br>**トップ / パーツ / LOG** |

**Root → Category で変わるのは scope（母集団）だけ。見られるものの種類は変えない。**

```
すべてのRCカー → RIG    = 全RIG
Rock Crawler  → RIG    = Rock CrawlerのRIG

すべてのRCカー → パーツ  = 全RIGに現在装着されているパーツ
Rock Crawler  → パーツ  = Rock CrawlerのRIGに現在装着されているパーツ

すべてのRCカー → LOG    = 全RIGに紐づくLOG
Rock Crawler  → LOG    = Rock CrawlerのRIGに紐づくLOG
```

### Domain間の対称性は要求しない

RIG系4本 / PARTS系3本の非対称は **037 の判断のまま維持する**。
`すべてのパーツ → 装着RIG` `モーター・ESC → 装着RIG` は主ナビにしない。装着RIGは発見棚で足りる。

**つまり判断基準は2階建てになった。**

| 方向 | 基準 |
|---|---|
| **Domain内（縦）** | **継承する。** 需要判定を持ち込まない |
| **Domain間（横）** | **閲覧需要の非対称性で決める。** 揃えない |

## 2. 🔴【L1】037 §1 の何を失効させるか

037 §1 の見出しは「全面共通の4軸は失効。**面ごとに本数が変わる**」だった。

| 037 §1 の主張 | 本裁定での扱い |
|---|---|
| 全Browse面で共通の4軸を強制しない | **有効。** 全面共通4軸は復活させない |
| WORLD ROOT（HOME）にローカルナビを置かない | **有効** |
| 軸化の基準は「押したくなるか / 閲覧需要の非対称性」 | **Domain間に限定して有効**。Domain内には適用しない |
| RIG ROOT = `トップ / RIG / LOG` | 🔴 **失効。** `トップ / RIG / パーツ / LOG` へ |
| 「ROOTは構造上のHubなので軽くする」 | 🔴 **失効。**（§4 に置き換え） |

### 失効の根拠

037 の基準そのものが間違っていたのではない。
**適用範囲を間違えた。** Domain間の説明として作った基準を、Domain内の縦方向にも使った。

その結果 RIG ROOT だけが**子より閲覧能力の低い親**になった。
037 の時点では4面を実画面で並べていなかったため、この段差は見えていなかった。
**2026-08-31 の PC/Mobile 4面同時比較が改訂根拠である。**

> **記録:** L1 を改訂するので、黙って書き換えず失効理由をここに残す。
> 「より良い案が出たらL2は更新する」は CORE の方針だが、
> **L1 は失効理由の明示を伴わなければ改訂しない。**

## 3. 🔴【L1】書き方の注意 —「深さで軸を変えない」とは書かない

HOME（WORLD ROOT）にはローカルナビが無い。
「深さで軸を変えない」と書くとこれと矛盾する。

**正しい言い方: 「同一Domain内では継承する」。**
HOME は RIG Domain でも PARTS Domain でもなく、**Domainの外側**（RCカーWORLDの入口）。
継承の話が始まるのは Domain Root からである。

---

## 4. ROOTページは維持する。HOME統合・ROOT削除はしない

検討過程で「`すべてのRCカー` にパーツを足すと総合トップと役割が同じになり、
ROOTが不要になるのでは」という説が出た。**採らない。**

| 面 | 役割 |
|---|---|
| **RCカー HOME**（WORLD ROOT） | RCカーWORLDへの入口。RIG/PARTSのDirectory、カテゴリ発見 |
| **すべてのRCカー**（RIG ROOT） | **RIGを起点に**世界を見る |
| **すべてのパーツ**（PARTS ROOT） | **PARTSを起点に**世界を見る |

RIG ROOT にパーツ軸を足しても PARTS ROOT と同じ面にはならない。母集団が違う。

| | 定義 | MOCK実測 |
|---|---|---|
| `すべてのRCカー → パーツ` | 全RIGに**現在装着中**のパーツ<br>`rig_parts.removed_at IS NULL` の DISTINCT `part_id` | **12,480** |
| `すべてのパーツ → パーツ` | 登録されている**全パーツ**そのもの | **18,492** |

**「ROOTがHOMEと重複している」という違和感の正体は、
ROOTの存在ではなく RIG ROOT だけ閲覧能力が欠けていたことだった。**
継承を通した後は3者の役割が分かれて見える。

ROOT削除を再検討するとすれば、この状態で実画面を使ってなお重複感が残った場合のみ。

## 5. 🔴 副作用として顕在化した 036違反 2件

RIG ROOT にパーツ軸を足した瞬間、**Mobile RIG ROOT のパーツviewが真っ白**になった。

036 裁定の PARTS 表示グループは `part` / `parts` / `part_master` の3種。
これが5か所に分散実装されており、**2か所で別々の型が抜けていた**。

| 場所 | 欠けていた型 | 状態 |
|---|---|---|
| `css/mobile-shell.css` | `part` | **顕在化。** RIG ROOTの「使用パーツ」棚が全消え |
| `pc/myrig-browse-category-v3.html` | `parts` | 潜在。該当棚を足した瞬間に消える |

いずれも**判定側だけ**を直した。`data-entity-type` は書き換えない（036のまま）。

> **教訓:** 軸を1本足すという小さな変更が、休眠していたバグを起こす。
> 「今は影響が無い」不整合は、影響が出る変更が来るまで待っているだけである。

> **PENDING（別トラック）:** 表示グループ判定が5か所に分散している件の集約。
> 今回はリファクタしない。集約するまで、同種の抜けは再発しうる。

## 9. PENDING — セクション並びパターンは「今は作らない」

Next.js 実装時に、各面の右側セクション並びをパターン化し、
管理画面で「Rock Crawler は Aパターンをベースに一部差し替え」のように
運用したい構想がある（イタヤ）。

**今は作らない。** 理由と再開条件を残す。

### なぜ今作らないか

**実装済みの Category面が Rock Crawler と モーター・ESC の2つしかない。**
2例から3パターンは導出できない。今作れば、実データではなく想像を正典に固定することになる。

### 再開トリガー

**3つ目の RIG Category（ドリフト等）を作るとき。**
そこで初めて「Rock Crawler と何が同じで何が違うか」が実物で出る。

### 設計上の注意（先に置いておく）

**A/B/C を「レイアウト」として設計しない。**

Rock Crawler と モーター・ESC の違いは、セクションの並び方ではなく
**どの関係棚が成立するか**だった。本裁定そのものがその証拠である。

したがってパターンの軸は3つの記号ではなく、

```
Domain（RIG系 / PARTS系） × セクションレジストリ（並び順つき）
```

になるはず。不透明な記号3つにすると、後から「AとBの差は何だったか」を
誰も説明できなくなる。
