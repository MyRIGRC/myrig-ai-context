## 1. 全体の骨組み（PC・1280px 以上）

```
┌ 上の帯（高さを低く）: MyRIG Admin ｜ 区画 [App] [Catalog] ｜ 検索（#ID・username・URL を貼る）｜ 自分（再確認の状態・ログアウト）
├ 左の列（細い・文字だけ）           ├ 本文
│ 今日やること   （件数）           │
│ 受付箱         （件数）           │
│ ─ 人と投稿 ─                     │
│ 投稿 / ユーザー                   │
│ ─ データ ─                       │
│ 退会・保存・保全 / 書き出し        │
│ ─ 発信 ─                         │
│ お知らせ / 購入先                 │
│ ─ システム ─                     │
│ 処理と費用 / 操作の記録（B）      │
```

- **左の列の件数は「要対応」だけ**（新着の総数は出さない。0 なら件数を出さない）
- **上の検索は何でも受ける**: `#1042`（案件）・`@username`・利用者の画面の URL を貼る → 該当の案件・ユーザー・投稿へ直接飛ぶ。運営が利用者の画面で問題を見つけたとき、URL を貼るだけで処置できる（M5「自分で見つけた問題」の入口）
- Catalog 区画（B）は同じ骨組みで左の列だけ変わる。区画を切り替えると色ではなく**見出しの文字**で分かるようにする（A-2）

### 状態の見せ方（A-2）
| 状態 | 見せ方 |
|---|---|
| **急ぎ**（R2・処理の停止・管理者の異常） | 行の左端に太い帯 ＋「急ぎ」の文字。いちばん強い |
| **期限切れ** | 「期限切れ 2 日」の文字 ＋ 強い枠 |
| **今日まで / 明日まで** | 「今日まで」の文字 |
| 要対応 | 通常 |
| 待ち（照会中など） | 弱く。「待ち・あと 4 日」 |
| 済み | 一覧に出さない（絞り込みで見る） |

- 色は状態にだけ使う。カテゴリの色（RIG 黄・PARTS 赤・LOG 青）は使わない。**色だけに頼らず、必ず文字を添える**

## 2. Admin Home（今日やること）

**並び（上から・固定）**
1. **急ぎ** — R2 緊急の申し立て・処理の停止・管理者のログイン異常・漏えいの疑い。1 件ずつ大きく
2. **期限** — 期限切れ → 今日まで → 明日まで（`admin_case_deadlines` から）
3. **処理の失敗** — 止まった Job（退会の確定・保存期間・メール）と、費用の通知（75% 以上）
4. **新しい受付** — まだ案件になっていない受付（`admin_case_sources` に無いもの）を種類ごとに件数で
5. **承認待ち** — 個人サイトのリンク（優先度は低い・いちばん下）

- **全部 0 のとき**: 画面の中央に「対応が必要なものはありません」と、最後に確かめた時刻だけ
- 数字のグラフ・PV・登録数は置かない（Analytics は C）
- 開いたときに読むだけ。自動で更新しない（右上に「更新」）

## 3. 受付箱（/admin/cases）

### 一覧
| 列 | 中身 |
|---|---|
| 状態 | 急ぎ / 期限切れ / 今日まで / 要対応 / 待ち |
| #ID | 案件の番号 |
| 種類 | 投稿の通報・コメントの通報・ユーザーの通報・プロフィール・権利侵害・緊急・違法・お問い合わせ（種別）・異議・リンク承認 |
| 対象 | 投稿の題名 / username（縮小画像 1 枚まで） |
| 受付の数 | 同じ対象への通報が何件まとまっているか |
| 期限 | いちばん近い期限 |
| 最終更新 | |

- **並び**: 急ぎ → 期限の近い順 → 受けた順。並べ替えは「受けた順」「最終更新」だけ
- **絞り込み**: 状態・種類・期限あり・保全あり・日本の外。絞り込みは URL に残す（ブックマークできる）
- **まだ案件になっていない受付**は、一覧の上に「新しい受付 12 件 → まとめて案件にする」。同じ対象への通報は自動で 1 つの案件にまとめる（まとめ方の候補を出し、運営が確定）
- 1 ページ 50 件・カーソルでページ分け（v1.0 §7）

### キーボード
`j / k` 上下 ・ `Enter` 開く ・ `/` 検索 ・ `g h` Home ・ `g c` 受付箱

## 4. 案件の詳細（/admin/cases/:id）

```
┌ 見出し: #1042 投稿の通報 ・ 状態 ・ 期限 ・ 保全あり/なし
├ 左（広い）                              ├ 右（操作・幅は固定）
│ ① 対象: 投稿のプレビュー（利用者の画面   │ 決定: [非表示] [維持] [停止へ] [保留]
│    と同じ見た目・運営の非表示も見える）   │  → 理由の条を選ぶ（必須）
│    「利用者の画面で開く」                │  → 通知の文（ひな形から・編集可）
│ ② 受付: まとまった通報・お問い合わせ     │  → 確認 → 実行
│    （元の表から読む・利用者の文は        │ 期限: 一覧と追加（制度・数え始め・暦日/営業日）
│     そのまま表示。写さない）             │ 保全: かける / 見る（範囲つき・D3）
│ ③ やりとり: 送った文・返事               │ 関連: 同じユーザーの過去の案件・停止歴
│    （admin_correspondence）              │ 内部メモ
│ ④ この案件の操作の記録（Audit から）     │ AI に渡す（B: Task Package）
```

- **決定ボタンは種類ごとに変わる**（通報 = 非表示 / 維持 / 停止へ ・ 権利侵害 = 根拠を求める / 一時非表示 / 照会 / 削除 / 維持 ・ お問い合わせ = 返信 / 別の案件へ / 終了）
- **取り消せない操作**（停止・削除・保全の解除）は、理由の入力 → もう一度の本人確認（step-up）→ 実行
- **「したこと」の通知は、実行が終わってから送る**。送信の結果（送った / 失敗）を ③ に出す
- 元のデータが消えていても落ちない: ① に「対象は消去済み（日時）」と出す
- **緊急（R2）の案件**: ① に画像を出さない（「画像は表示していません。利用者の画面で確認」）。AI に渡すボタンは出さない

## 5. /admin/m（Mobile の緊急の面）

```
急ぎ 2 件
─────────────────
#1042 同意のない性的な画像 ・ 投稿 ・ 19:02
 [一時非表示（画像の配信も止める）]
 [投稿者を一時停止]
─────────────────
#1043 管理者ログインの異常 ・ 18:40
 [すべてのセッションを切る]
```

- 理由は選ぶだけ（自由入力なし）。押す前にもう一度の本人確認
- 取り消し・詳しい判断は PC。「PC で開く」のリンクだけ
- 非常ベルのメールの入口から、ここに直接来る
