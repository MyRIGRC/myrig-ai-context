## /search トップ — 入口2層 ＋ 開閉軸

**Mobileのみ。PCには独立した検索トップを設けない**（ヘッダー検索から結果へ直行。2026-08-23 裁定）。

ロゴ → SearchHeader（検索欄統合・戻るなし）→ 最近の検索 → **入口2層** →
選んだパネル（同一画面）→ 固定バー「この条件で検索」。

### 入口は「対象」と「方法」の2層（2026-08-24 改訂）

対象で表せるものと、方法でしか表せないものを厳密に切り分ける。
**両方に同じ4枚グリッドを置くと「どちらを押すのか」が発生する**ため、重複させない。

**MyRIGで探す（対象・4枚）** — RIG / パーツ / LOG は検索結果へ直行（`?type=`）

| 対象 | 補足 | 遷移 |
|---|---|---|
| RIG | みんなのマシン・作例 | `search-results.html?type=rig` |
| パーツ | 装着例から探す | `search-results.html?type=parts` |
| LOG | 改造・メンテ記録 | `search-results.html?type=log` |
| ビルダー | 好きな作例の人を探す | 同一画面パネル（`data-how="user"`） |

**もっと詳しく探す（方法・3枚 `data-how`）**

| 値 | ラベル |
|---|---|
| `cond` | 条件で探す |
| `pn` | 製品名・型番で探す |
| `myrig` | 自分のRIGから探す |

> 🔴 **旧仕様（失効）**: 「探し方」4枚 = 条件で探す / 型番で探す / 自分のRIGから探す /
> 人・ガレージを探す。
> **失効理由**: 検索トップが「操作」だけで、MyRIGで何が探せるのか分からない状態だった。
> 対象の層を足しつつ、対象で表せる「人・ガレージ」は対象側へ移設した。
> **「人・ガレージ」→「ビルダー」**（ボトムナビの「ガレージ」＝自分のガレージと衝突するため。
> 実データを見て再検討の余地は残す）。

### 「条件で探す」の開閉軸 5本（`data-ax`）

| 値 | 見出し | 件数 |
|---|---|---|
| `type` | 種別 | **3（RIG/パーツ/LOG）**。製品情報は2026-08-24に撤去、ユーザーは対象カード側 |
| `scat` | 車種カテゴリ | 24 |
| `pcat` | パーツカテゴリ | 親14 |
| `maker` | メーカー | — |
| `scale` | スケール | 13（`data-size-class`。※値集合はHOLD） |

「すべて開く」トグルあり。

### 検索窓のプレースホルダ

全面で **`RIG・パーツ・LOGを検索`** に統一（製品情報を対象外にしたため）。
「製品名・型番で探す」選択時のみ `製品名・型番を入力（例: TRX-4）`、
ビルダーのパネルでは `ユーザー名・ガレージ名を検索`。

## 検索結果

- **SearchHeader**（戻る = fallback `/search`）
- **コンテンツタイプ4本・件数つき**（すべて / RIG / パーツ / LOG）。実装は `.filter-chip` のチップ列
- **絞り込みSheet** ＋ 件数バッジ ＋ 適用中条件チップ

### 対象は Community 3種のみ（2026-08-24 SEARCH-UPDATE-001）

標準検索 = MyRIGコミュニティの投稿を探す面。**製品情報とユーザーは対象外**
（結果・チップ・件数のすべてから除外）。製品情報は Library、人は「ビルダー」探索の責務。

- 「すべて」は独立した状態ではなく、**3種すべてONかどうかの計算値**
- 「すべて」から個別を押す → その種別だけに絞る
- 全部OFFになったら「すべて」へ自動復帰
- **表示件数は選択中チップの合計と常に一致**（隠れたプリセットを持たない）
- `?type=rig` は独立ページではなく、**同一ページの初期フィルター指定**

### 「すべて」= RIG/パーツ/LOGのブレンド（2026-08-24 改訂）

3種をラウンドロビンで1本のストリームに混ぜ、関連度順に流し込む。PC/Mobile共通。
種別ごとに区切らない。

> 🔴 **旧仕様（失効）**: 「すべて」= ダイジェスト29件（RIG8/パーツ8/製品4/LOG6/ユーザー3、
> 表示順 rig→parts→lib→log→user、各セクションに「◯◯の結果をすべて見る →」、無限にしない）。
> **失効理由**: 実機で種別スキップが発生した。パーツを探している人がRIG欄を丸ごと飛ばす。
> カテゴリ別展示棚であって検索の振る舞いではない。

> 🔴 **旧仕様（失効）**: 種別タブ = 無限スクロール（6件ずつ・ページ送りUIなし・
> 6件に1枚のフルワイド注目枠 FEATURED）。
> **失効理由**: 種別を独立ページとして扱うのをやめた。FEATUREDは廃止
> （ブレンド結果の途中に別ロジックのカードを挟むと「上から関連度順」の期待を壊す）。

### ソート（2026-08-24 改訂・裁定⑦⑧を上書き）

| 選択状態 | 選択肢 |
|---|---|
| すべて / 2種選択 / 0件 | **関連順 / 新着順**（種別を跨いで定義できるのはこの2つ） |
| 単一種別のみ | その種別固有の選択肢（下表） |

> 🔴 **旧仕様（失効）**: 「すべて」タブはソート行を出さない（横断ソートは定義不能）。
> **失効理由**: 3種をラウンドロビンで1本のストリームにしたことで、関連順・新着順は
> 横断でも定義可能になった。

**「人気順」は使わない。** 何で並んでいるかを名指しする。

| 種別 | 選択肢 |
|---|---|
| RIG | 関連順 / 新着順 / いいね順 |
| パーツ | 関連順 / 装着例が多い順 / 新着順 |
| LOG | 関連順 / 新着順 / いいね順 |

既定は全種別「関連順」。（製品情報・ユーザーの行は対象外化に伴い削除）

### Library補助導線（2026-08-24 新設）

製品情報は主結果に混ぜないが、Libraryが行き止まりにならないよう導線だけ置く。

**固定する（責務）**

- **Community件数には合算しない**（別母集団）
- 検索結果カードと**同じ見た目にしない**（結果の一部に見せない）
- **1回だけ**。繰り返さない（繰り返すと広告になる）
- 広告・アフィリエイトではない。購買導線はLibrary側の責務

**固定しない（実装・モック側のチューニング）**

件数 / 位置 / カードサイズ / 差し込み位置。現時点の実装値と、そう決めた理由・踏んだ罠は
`_decisions/2026-08-24_search-community-scope-v1.md` を参照。
数値を動かすのに裁定は要らない（CORE「正典化判断基準」）。

### 表示形式

RIG / パーツ / LOG = 共通カードのグリッド（PC 4列 / Mobile 2列）。空状態 = `.m-empty`。
種別によってグリッドとリストを出し分けない（ブレンドするため外形を揃える必要がある）。

## スコープ定義

実装 `search-results.html` の定数群が一元定義。

| 定数 | 内容 |
|---|---|
| `COMMUNITY` | rig / parts / log（標準検索の対象はこの3種のみ） |
| `LIB_DATA` / `LIB_TOTAL` / `LIB_AT` | Library補助導線用。**Community件数とは別母集団** |
| `SORT_OPTIONS` | 単一種別選択時のみ使用（横断時は関連順・新着順） |

**プレースホルダ基準文言: `RIG・パーツ・LOGを検索`**
モバイルは探し方でスコープ連動（製品名・型番 → `製品名・型番を入力（例: TRX-4）`、
ビルダー → `ユーザー名・ガレージ名を検索`）。

> 🔴 **旧定義（失効）**: `LABEL`=5種 / `UNIT`=台点件件人 / `GRIDTYPE`=rig,parts,lib /
> `DIGEST`=rig8,parts8,lib4,log6,user3 / プレースホルダ `RIG・パーツ・LOG・製品情報を検索`。
> 対象を Community 3種に限定し、ダイジェストを廃止したため。
