## 1. 確定パレット

| 種別 | 値 | 上に乗る文字 | 色相 | 彩度 |
|---|---|---|---|---|
| **RIG** | `#FBFF00` レモンイエロー | 黒 `#151515` | 61° | 100% |
| **PARTS** | `#D92D20` レッド | 白 `#ffffff` | 4° | 74% |
| **LOG** | `#2F5F8F` スチールブルー | 白 `#ffffff` | 210° | 51% |

**両モードで同じ値を使う。ライトモード用にくすませない**（**NG-3**、design-nogo-list.md 参照）。

### この組み合わせの根拠

- **彩度が 100% → 74% → 51% と階段状に下がる。** RIGが主役、PARTSが次、LOGは静かに支える。
  イタヤ裁定「LOGって、ある意味目立つ色じゃ無くても良い」と一致する。
- **色相が十分に離れている。** RIG↔PARTS 57° / RIG↔LOG 149° / PARTS↔LOG 154°。
- 旧v7の「緑×橙」は色覚特性上もっとも見分けにくい組み合わせだったが、本案では解消。
- スチールブルーはGPT提案 A Workshop から採用（イタヤ評「目がチカチカしないブルー」）。

### コントラスト実測

| | 文字 | 白地 | 黒地 |
|---|---|---|---|
| RIG `#FBFF00` | 黒 16.87 | 1.08 | 17.97 |
| PARTS `#D92D20` | 白 4.83 | 4.83 | 4.03 |
| LOG `#2F5F8F` | 白 6.66 | 6.66 | **2.92** |

**裁定済み（2026-08-17 / P22-B19）**: LOG のダークモードでの背景差が 2.92 で基準3.0をわずかに下回るため、
**ダーク時のみ `#3F709E` を採用する**（黒地 3.9）。これは「くすませ」ではなく同一色相内の明度調整なので
NG-3 には抵触しない（design-nogo-list.md NG-3「代替」項・NG-7 職域表に反映済み）。

```css
:root { --cat-log:#2F5F8F; }
[data-theme="dark"] { --cat-log:#3F709E; }
```

## 2. バッジの輪郭処理

**枠もスクリムも付けない。**（イタヤ裁定 2026-07-29「縁はいらないね。グラデもいらない。見えなきゃ見えないでいい。」）

### 前提として測った事実

カード上のバッジが乗る領域の輝度を、MyRIG実画像68枚で実測した結果、**0.03〜1.00 と全域にばらついた**
（中央値0.37、彩度の中央値7%＝ほぼ無彩色）。

そのため**どのパレットを選んでも、枠なしでは半数以上の写真で輪郭が立たない**。

| 案 | RIG | PARTS | LOG |
|---|---|---|---|
| GPT A Workshop | 56% | 50% | 59% |
| GPT D Quiet | 50% | 56% | 54% |
| 黄/赤/青 | 65% | 74% | 63% |

**結論: バッジの可読性は色相ではなく輪郭処理で決まる。**
色相の選択は機能ではなく世界観の問題として扱ってよい。
イタヤ裁定により輪郭処理は行わないので、白い写真の上で RIG バッジが見えなくなるケースは**許容**する。

## 3. 色の職域（旧v7からの最大の変更）

旧v7では緑が ①ブランド色 ②RIGカテゴリ色 ③運用中ステータス色 ④ボタン・選択状態の色 を
兼ねており、これが「モバイルで緑が画面中に出る」原因だった。v8では分離する。

- **カテゴリ色**（黄・赤・青）: 種別の識別のみ。バッジ、小さなチップ、アイコン
- **操作の色**: カテゴリ色から独立。**中立ソリッド（B案）で確定**（2026-08-17 イタヤ「これはBかな。
  黄赤青以外の色味はうるさすぎる。ナビ系は普通に白黒系でいい」）。
  **純黒・純白は使わない**（同発言「単純にベタ白黒っていうか、上手い事処理して、重くないようにして欲しい」）。

  **実値**（`css/mobile-shell.css`。design-nogo-list.md NG-7 の職域表と一致）:

  ```css
  /* light */
  --color-action-primary: #1F2328;       /* 純黒より一段柔らかい黒 */
  --color-action-primary-text: #ffffff;
  --color-action-quiet-bg: #EFF1F3;

  /* dark */
  --color-action-primary: #E6EDF3;
  --color-action-primary-text: #0D1117;
  --color-action-quiet-bg: #21262D;
  ```

  **「Bottom Nav 中央の『＋登録』のみブランド色」は不採用**（再提案しないこと）。
  中央の `.create-circle` も `--color-action-primary` ＝中立黒を使う。

  **PC側は未トークン化。** PC に `--color-action-primary` は存在せず、中立操作色は
  `#24292f` / `#1f2328` でハードコードされ light が2値に分裂している。統一するなら `#1F2328` 側へ。
- **ステータス色**: `--rig-status-*` として別系統を維持
- **ブランド色**: 未裁定（黄をRIGカテゴリに使うため、ブランド色は別に立てるか持たないか要判断）

## 4. 実装上の注意（実装前に必ず読む）

- `--cat-*` の参照は全体で **1,230箇所**（モバイル645 / PC585）
- `background: var(--cat-rig); color:#fff` という書き方が20以上のファイルにある。
  **レモンイエローに白文字はコントラスト1.08で読めない。**
  対の文字色トークン `--cat-rig-on: #151515` 等を新設し、機械置換すること
- `--cat-rig` が**ボタンの色としても使われている**（検索ページの「この条件で検索」、
  登録ページの保存ボタン等）。そのまま色を変えると検索ボタンまで黄色になる。
  操作系は `--color-action-primary`（B17で敷設済み）へ移すこと

## 5. 却下された案（再提案しないこと）

- **緑・紫・橙の維持**（v7）: 白地で緑と橙に白文字が乗らない（2.47 / 2.57）。
  紫だけが極端に暗く（8.83）ヘッダーで沈む。3色の重さが揃わない構造的欠陥
- **GPT A Workshop フルセット**: PARTS=ガンメタル `#4B5563` は彩度11%でほぼ無彩色。
  「色あり＝ユーザー投稿 / 色なし＝公式データ」というMyRIGのルールを壊す
  （ブルー `#2F5F8F` のみ LOG として採用）
- **全部を黄バッジに統一**: 3種が同色なら色は種別情報を運ばない。色分け廃止と実質同じ
- **中立＋色線**（片側だけ色線の角丸ボタン）: NG-1。イタヤさんが繰り返し明確に拒否
- **ライトモードでのくすませ**: **NG-3**。別の色になってしまう
